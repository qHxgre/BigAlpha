# C03 因子构建过程说明

## 0. 关键研究约束与任务指令摘要

以下内容是根据 C03 的实际研究链路整理出的关键任务约束，用于说明因子是在什么研究边界下构建的，并非逐字输入记录。

```text
你是一名量化研究员，目标是参加 BigAlpha 2026 AI 因子挖掘赛道。

比赛只允许使用：
bigalpha_2026_stock_bar1m
bigalpha_2026_financial
bigalpha_2026_instruments
bigalpha_2026_factorlib
bigalpha_2026_exposure

每次提交必须定义 main(datasources, start_date, end_date)，返回且仅返回
date、instrument、factor 三列。因子为日频，股票池为历史中证1000成分股。

评分的重要部分来自 Elastic Net 增量贡献，因此候选因子应当低相关、
可解释、能够通过 DAI SQL 高效计算。禁止未来数据、外部数据和外部网络。

研究输出需要包含：
经济假设、字段需求、DAI SQL 计算逻辑、方向解释、合规风险、
smoke test 结果和可提交代码。
```

C03 的专属研究任务是在上述约束下，围绕一个独立的盘口微观结构假设构造低复杂度候选：使用近档/远档深度结构确认隔夜缺口的日内吸收或修复，并避免输入 R04、F18 或其他已提交复合因子。

## 1. 因子定位

C03 是一个盘口深度结构与隔夜缺口修复因子。它的定位不是替代 R04 这类多信号蒸馏因子，而是作为信息来源差异较大的补充因子：R04 更偏多信号微观结构组合，C03 则聚焦于“盘口结构是否支持隔夜缺口在日内被修复”这一特定市场微观结构现象。

最终提交文件：

```text
submission_c03_depth_structure_gap_repair.ipynb
```

## 2. 构造假设

C03 的核心假设是：

```text
如果某只股票出现隔夜缺口，而日内价格表现出吸收或修复迹象，同时盘口近档买盘相对远档买盘更有支撑、卖盘压力相对更弱，则该股票的短期价格修复行为可能更稳定。
```

因此，因子不是单独使用隔夜缺口，也不是单独使用盘口深度，而是构造“盘口深度结构 × 缺口修复行为”的交互信号。

## 3. 研究迭代过程

C03 的研究过程从一个较窄的微观结构问题开始：盘口深度形状能否对隔夜缺口的日内修复提供条件确认。与 R04 的多信号模型蒸馏不同，C03 刻意保持单一假设和短链路公式，便于作为主因子之外的信息补充。

迭代过程中主要遵守以下约束：

- 只使用分钟行情和盘口原始字段。
- 不输入已提交因子、复合因子或其他模型输出。
- 中间变量均按日截面标准化，避免尺度差异主导结果。
- 交互项必须有明确经济含义，不能只做无解释的非线性组合。
- 截止前若变体触发平台检测风险，则优先保留原始可解释版本。

该因子的最终形态来自三步收敛：

```text
盘口近远档深度差异
-> 隔夜缺口与日内吸收/修复
-> 深度结构对缺口修复的条件确认
```

因此，C03 更像一个结构确认型因子，而不是一个宽特征机器学习因子。

## 4. 原始数据与日频聚合

C03 使用分钟级行情和盘口字段，先聚合为日频特征。主要字段包括：

- 日内开盘价、收盘价、昨收价。
- 日内最高价、最低价。
- 近档买盘深度：`bid_volume1 + bid_volume2 + bid_volume3`。
- 近档卖盘深度：`ask_volume1 + ask_volume2 + ask_volume3`。
- 远档买盘深度：`bid_volume4 + bid_volume5`。
- 远档卖盘深度：`ask_volume4 + ask_volume5`。
- 成交额、成交量、成交笔数。
- microprice 偏离。

这些字段均来自提交环境中的原始行情与盘口数据，不依赖其他已提交因子。

## 5. 盘口深度结构信号

第一部分刻画盘口近远档结构。直觉上，如果近档买盘相对远档买盘更集中，而近档卖盘相对远档卖盘没有同等压力，则盘口结构更有利于价格支撑。

构造方式：

```python
depth_slope = log1p(bid_depth_1_3 / (bid_depth_4_5 + 1)) \
            - log1p(ask_depth_1_3 / (ask_depth_4_5 + 1))
```

其中：

- `bid_depth_1_3` 表示买一至买三深度。
- `ask_depth_1_3` 表示卖一至卖三深度。
- `bid_depth_4_5` 和 `ask_depth_4_5` 表示远档深度。

该变量用于捕捉近档买卖盘支撑的相对强弱。

## 6. 隔夜缺口与日内吸收

第二部分刻画隔夜缺口是否在日内被吸收或修复。

日内收益：

```python
intraday = day_close / day_open - 1
```

隔夜缺口：

```python
gap = day_open / pre_close - 1
```

吸收项：

```python
absorption = -gap * intraday
```

该吸收项的含义是：

- 如果高开后日内回落，说明缺口被市场吸收。
- 如果低开后日内修复，说明价格有回补力量。
- 通过 `-gap * intraday` 将缺口方向和日内反向修复统一到同一表达中。

## 7. 缺口修复强度

为了避免单纯奖励大缺口，C03 将吸收项、日内收益和缺口绝对幅度组合为缺口修复强度：

```python
gap_repair = rank_z(absorption) + 0.5 * rank_z(intraday) - 0.35 * abs(rank_z(gap))
```

这样设计的原因是：

- `rank_z(absorption)` 捕捉缺口被吸收或修复的程度。
- `0.5 * rank_z(intraday)` 保留日内价格方向信息。
- `-0.35 * abs(rank_z(gap))` 惩罚过大的隔夜跳空，避免因子只追逐极端缺口。

## 8. 深度结构与缺口修复交互

最终因子将盘口深度结构与缺口修复强度做交互：

```python
raw = rank_z(depth_slope) * rank_z(gap_repair)
factor = rank_z(raw)
```

交互项的含义是：

```text
只有当盘口结构和缺口修复行为同时提供支持时，信号才更强。
```

这比简单线性加总更强调条件确认，符合 C03 作为结构型补充因子的定位。

## 9. 标准化与输出

C03 在每日截面内对中间变量进行 rank-z 标准化，降低极端值和尺度差异影响。最终输出与比赛提交格式保持一致：

```text
date, instrument, factor
```

输出时再与官方股票池合并，缺失值填充为 0，确保所有提交日期和标的都有合法因子值。

## 10. 变体尝试与最终保留原始 C03

研究后期曾尝试对 C03 做平滑变体，希望类似 R04 一样提高稳定性。但多个 C03 平滑版本触发平台未来函数检测。考虑到临近提交截止，最终停止 C03 平滑方向，保留原始 C03 版本。

最终保留原始 C03 的原因：

- 原始 C03 可以作为 R04 之外的信息源补充。
- C03 与 R04 的信号来源差异较大，相关性风险低于同族平滑变体。
- 平滑版本存在平台检测风险，不适合截止前继续尝试。
- 原始 C03 的逻辑清晰、结构紧凑、可解释性强。

## 11. 最终因子摘要

C03 可以概括为：

```text
基于高频盘口近远档深度结构、隔夜缺口、日内收益和缺口吸收行为构造的结构确认型微观因子，通过“盘口深度结构 × 缺口修复强度”的交互关系识别短期价格修复机会。
```
