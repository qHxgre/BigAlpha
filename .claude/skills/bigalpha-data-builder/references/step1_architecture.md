# Step 1：架构设计确认

在生成任何代码前，先与用户对齐以下要素，全部确认后再进入 Step 2。

## 必须确认的要素

1. **目标表名**：小写下划线形式，如 `bigalpha_stock_bar1m_zz1000`。
2. **业务用途**：这张表服务于什么场景（因子库 / 行情快照 / 财务衍生 等）。
3. **主键（unique_together）**：通常是日期 + 标的，或日期 + 标的 + 其他维度。
4. **分区策略**：
   * 日频及以上粗粒度 → 按**年**分区
   * 分钟频及以下高频 → 按**月**或**日**分区
5. **数据源**：底层引用哪些 BigQuant 表（如 `cn_stock_bar1m`、`cn_stock_factors` 等）。
   * 若用户没说清楚，引导其参考 [datasource_reference.md](./datasource_reference.md)。
6. **时间范围/调度方式**：是回填历史还是按日增量。
7. **关键字段清单**：业务字段名 + 含义 + 类型（粗略即可，详细类型在 Step 2 落实）。

## 输出格式

用一段简短的"需求确认表格"复述给用户，例如：

```
- 表名：bigalpha_stock_bar_1m_zz1000
- 用途：中证1000成分股 1 分钟行情
- 主键：date + instrument
- 分区：按月（%Y%m）
- 数据源：cn_stock_bar1m + 中证1000成分名单
- 字段：open / high / low / close / volume ...
```

明确询问用户："以上理解是否正确？确认后我会进入 Step 2 生成 schema.py。"

## 注意事项

* 不要在本步骤生成任何代码。
* 如果信息不足，针对性追问，不要一次抛 5 个以上问题。
* 用户确认后再继续。
