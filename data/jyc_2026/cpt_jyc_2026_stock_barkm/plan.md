# 快照合成 1 分钟行情

代码：`minute_builder.py` 的 `OneMinuteBarBuilder.build`。输入是 `cn_stock_level2_snapshot`（约 3 秒一条），输出是左闭右开、标在区间末端的 1 分钟 bar。

## 1. 输入与输出

- 输入关键字段：`date, instrument, price, pre_close, bid_price1, ask_price1`，以及日内累计字段 `volume, amount, num_trades`，外加五档盘口。
- 输出：`open/high/low/close`，区间增量 `volume/amount/deal_number`，`pre_close` 和五档盘口取分钟内最后一条快照。

## 2. 合成步骤

1. 按 `instrument, date` 排序，给每条快照打分钟标签（第 3 节），无标签的快照丢弃。
2. 对交易时段内的原始累计字段直接差分得到增量，不过滤、不修订快照。每个交易日首条快照的增量等于它自己的累计值。
4. 确定每条快照的价格（4.4），并用 `Δamount / Δvolume` 算相邻快照间的成交均价。
5. 按 `(instrument, 分钟标签)` 聚合：
   - 价格取 first / max / min / last 作为 OHLC；
   - 量额笔数取增量之和。
6. 用成交均价放宽 high/low（4.5），剔除无价无量的分钟行（4.6）。

## 3. 时间归属

区间左闭右开，bar 标在区间末端。

| 快照时间 | 标签 | 说明 |
|---|---|---|
| `[09:15:00, 09:25:00)` | 所在分钟的下一分钟（09:16 ~ 09:25） | 集合竞价逐分钟切分 |
| `[09:25:00, 09:30:00)` | 09:25 | 撮合结果，见 4.1 |
| `[09:30:00, 11:30:00)` | 09:31 ~ 11:30 | 连续竞价 |
| `[11:29:00, 11:31:00)` | 11:30 | 接纳上午收市后延迟几秒的快照 |
| `[13:00:00, 15:00:00)` | 13:01 ~ 15:00 | 连续竞价 |
| `[14:59:00, 15:01:00)` | 15:00 | 收盘窗口，多接纳 1 分钟 |
| `[11:31:00, 13:00:00)`、15:01 之后、09:15 之前 | 无 | 丢弃 |

## 4. 遇到的坑与特殊处理

### 4.1 集合竞价结果的时间戳不是 09:25:00（已修复）

- 现象：旧逻辑只接纳 `09:25:00` 整点快照，真实撮合结果快照在 09:25:03 前后，被丢弃。
- 后果：竞价成交量没有 bar 去接，被“每日首条有效快照取累计值”的规则并进 09:31，全市场的 09:31 bar 量额虚高。例如 000503.SZ 修复前 09:31 成交量 558800，其中 55800 是竞价量。
- 处理：`[09:25:00, 09:30:00)` 统一归入 09:25。修复后 000503.SZ 的 09:25 成交量 55800，09:31 为 503000。
- 原则：首条有效快照之前的累计成交，必须有对应的 bar 去接。

### 4.2 累计字段不做修订

- 先用时间标签剔除午休等无法归属到交易分钟的快照，再计算差分；上午收市后的延迟快照接纳至 `11:31:00`，剔除范围为 `[11:31:00, 13:00:00)`。
- 默认交易时段内的快照数据正确，`volume / amount / num_trades` 直接按股票、交易日对相邻快照差分。
- 构建过程不剔除累计值回退、量额不一致等快照，也不使用 `cummax` 修订源值。
- 快照异常若造成分钟量额为负、量额不一致或隐含成交价异常，统一交给 `tester.py` 检出。

### 4.3 有些分钟没有快照

分钟内没有任何有效快照时，这一分钟没有输出行，不做补齐。

### 4.4 价格为 0 或 NaN

- 优先用快照 `price`，仅 `price > 0` 才有效。
- 集合竞价时段 `[09:15, 09:30)` 内 `price` 为 0 或 NaN 时，用买一、卖一价的均值代替，两者只有一个 > 0 就用那一个。
- 买卖一价也都无效时价格为空。竞价早期很常见，修复前 2020-01-02 有 532 行。
- 回退窗口原来只到 09:25:00，与 4.1 一起扩到 09:30。

### 4.5 采样价会漏掉快照间的瞬时成交

- 现象：快照只记录当时的最新价。002912.SZ 在 14:24:42 的两条快照之间成交 8600 股，均价 125.76，快照价却是 126.06；14:25 这一分钟按采样价得到的 low 是 126.04，成交均价低于 low。
- 处理：相邻快照间的成交均价必然落在这段成交的真实最低、最高价之间，所以每分钟 `high = max(采样最高, 成交均价最大值)`，`low = min(采样最低, 成交均价最小值)`。
- 代价：
  - high/low 不再只来自采样价；
  - `test_implied_trade_price_is_inside_bar` 对这类分钟几乎恒成立，检出“混入累计量额”的能力变弱；
  - 若某只股票当天首条有效快照很晚，首条的累计均价跨度很长，会撑宽该分钟的 high/low。
- 不放宽、只修 4.1 时，2020-01-02 仍有 23 行越界。

### 4.6 停牌股与无价格分钟

- 现象：停牌股全天有快照，但 `price`、买卖一价、成交都是 0，聚合后 OHLC 全为 NaN。2020-01-02 的 002115.SZ、603960.SH、000029.SZ 在 `cn_stock_status` 中 `suspended = 1`。
- 处理：任一 OHLC 为 NaN 且 `volume == 0` 的行直接剔除。
- 保留：有成交但没有价格的行不剔除，让 `test_prices_are_valid_ohlc` 报错，避免悄悄丢数据。
- 副作用：停牌股没有分钟行，当日输出股票数小于快照侧股票数。2020-01-02 快照侧 1558 只，输出 1555 只，差额与这 3 只停牌股数量一致（未逐只核对）。

### 4.7 其他细节

- `first / last / max / min` 默认跳过 NaN，OHLC 四个字段要么都有值，要么都为空，不会出现部分为空。
- 盘口字段取分钟内最后一条快照，不是区间内汇总。
