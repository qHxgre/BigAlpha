## 2. 总体结论

当前工具已经覆盖私榜人工复核的主要方向，模块划分也比较清晰，可以作为 Notebook 交互分析工具使用。但它目前仍属于“分析函数集合”，还不是一套具备统一入口、风险分级、结果汇总、自动导出和放行判定能力的完整复核系统。

本次实跑得到以下核心结论：

1. **正式成绩计算正确。** 176 份提交的已存储 A 分、B 分和最终分与评分代码复算结果完全一致，不一致数为 0。
2. **成功提交、因子池和回归结果集合一致。** 三者均为 114 个对象，无遗漏、冗余、重复或非法回归字段。
3. **失败率较高。** 176 份提交中有 62 份失败，失败率为 35.23%，涉及 40 个参赛方，是本轮最优先的运营与公平性风险。
4. **最终排名明显依赖 A/B 权重。** 79 个成功提交在 A/B 权重扫描中的名次跨度不低于 20 名，34 个不低于 50 名，最大跨度达到 98 名。
5. **A 分内部四指标相对稳健。** 逐项移除 A 分指标后，最大名次变化为 9 名，没有出现极端跳变；相比之下，A/B 权重和 B 分定义是更主要的排名敏感来源。
6. **B 分替代口径会显著改变部分排名。** 加入入选率或权重波动惩罚后，27 个提交的最终名次最大变化不低于 10 名，2 个不低于 20 名，最大变化为 23 名。
7. **发现一组极高度相似因子。** 提交 `cf699d02-76c1-470c-8be8-672ee86043f7` 与 `5d7e506e-7698-4231-b89c-828b0449debd` 的抽样 Pearson 相关系数为 0.9994，应升级为人工核验项。
8. **现有“回归可疑因子”规则未命中任何对象。** 这不等于完全没有稳定性风险，更可能说明当前组合阈值偏严格，且规则对中低模型分但高波动的因子不敏感。

综合判断：**评分产物本身可以通过一致性和完整性校验，但在正式放榜前，仍应处理失败提交、核查高度相似因子，并明确 A/B 权重及 B 分稳定性口径是否符合赛事规则预期。**

## 4. 正式评分口径复核

### 4.1 A 分

成功提交按以下四个指标分别计算百分位排名：

- `ic_mean`
- `ic_ir`
- `sharpe_ratio`
- `stress_ic_ir`

A 分为四项百分位排名的等权平均：

```text
A = (rank_pct(ic_mean) + rank_pct(ic_ir)
   + rank_pct(sharpe_ratio) + rank_pct(stress_ic_ir)) / 4
```

这一口径的特点是：

- 对量纲和极端值相对不敏感；
- 只保留相对顺序，不保留指标差距大小；
- 同分处理依赖 Pandas 默认平均排名；
- 任一指标缺失会使该行的 A 分传播为缺失值，当前评分流程没有显式拒绝缺失指标。

### 4.2 B 分

B 分以回归 `model_score` 的百分位排名为基础：

```text
B = rank_pct(model_score)
```

但以下对象会被直接置为 0：

- `model_score <= 0`；
- 存在 `selection_rate` 字段且 `selection_rate <= 0`。

当前 B 分**没有直接使用** `abs_weight_mean`、`abs_weight_std` 和正的 `selection_rate` 大小。也就是说，只要入选率大于 0，入选 5% 与入选 100% 在 B 分公式中没有直接区别；权重很稳定与权重大幅波动也没有直接区别。

### 4.3 最终分

成功提交的最终分为：

```text
Final = 0.3 × A + 0.7 × B
```

失败提交统一记为 `-2.0`。

由于 B 分权重为 70%，最终排名天然更接近回归模型分排名。本次实跑也验证了 A/B 口径差异是最主要的排名敏感来源。

### 5.4 A 分四指标敏感性

逐项移除 A 分指标后：

- 最大最终名次变化为 9 名；
- 30 个提交的最大变化不低于 5 名；
- 未出现数十名级别的极端变化。

这说明四个 A 指标虽然存在较大的单项排名差异，但经过等权百分位平均并仅占最终分 30% 后，单个 A 指标对最终榜单的影响相对可控。

需要注意：当前“移除单项”实现会对保留指标重新计算百分位平均，但并未模拟指标权重细微扰动、指标截尾、并列排名方法变化或缺失值策略。这些仍可作为二阶段稳健性检查补充。

### 5.5 回归稳定性与 B 分稳健性

114 个成功因子的 `selection_rate` 分布如下：

| selection_rate | 因子数 |
|---:|---:|
| 0.357143 | 1 |
| 0.571429 | 1 |
| 0.714286 | 9 |
| 0.785714 | 19 |
| 0.857143 | 20 |
| 0.928571 | 31 |
| 1.000000 | 33 |

从离散步长看，本轮回归应包含 14 个滚动窗口。绝大部分因子的入选率较高，但仍有少数因子仅在 5/14 或 8/14 的窗口中入选。

当前稳定性函数定义：

```text
weight_cv = abs_weight_std / abs_weight_mean
stability_score = selection_rate / (1 + weight_cv)
```

并使用以下组合条件标记可疑对象：模型分前 20%，同时满足入选率后 10%、权重变异系数前 10%或模型排名与稳定性排名差达到总数 30%。本次结果为 0 个可疑对象。

该规则存在两个问题：

1. 只有高模型分对象才可能被标记，其他极不稳定对象会被忽略；
2. 多个分位数阈值叠加后过于严格，容易得到空结果。

建议将其拆成独立风险标签，而不是一个布尔值：

- `low_selection_rate`：入选率低于 0.70；
- `high_weight_cv`：CV 高于 1.0 或位于前 10%；
- `large_model_stability_gap`：排名差不低于 20；
- `high_score_low_stability`：模型分前 20%且稳定性后 30%；
- `award_boundary_risk`：最终名次处于获奖线附近且命中任一稳定性风险。

2. 按日期计算截面相关，再查看日度相关均值、分位数和时间序列；
3. 比较缺失值掩码是否一致；
4. 对两列分别做截面标准化后计算差值分布；
5. 映射参赛方信息，判断是否属于同一团队或规则允许的关联提交；

当前实现的技术限制：

- 先完整读入 322 MB Parquet，再抽样，内存节省有限；
- 等距按行抽样可能受到数据排序方式影响；
- 只计算总体 Pearson，无法区分时间相关与截面相关；
- 使用绝对相关会将接近完全反向的因子也视作高相似，需要在报告中保留符号；
- 没有配置最小重叠比例，低重叠样本也可能产生不稳定高相关；
- 没有把提交 ID 映射为参赛方，人工核验成本较高。

## 6. 当前实现的主要问题

### 6.1 P0：可能影响放榜正确性的问题

#### 6.1.1 成绩一致性检查可能漏掉集合差异

当前代码：

```python
comparison = stored.merge(recomputed, on="submission_id", suffixes=("_stored", "_recomputed"))
```

普通内连接会丢弃只存在于一侧的提交。应改为外连接并检查 `_merge`，同时使用 `validate="one_to_one"` 检测重复 ID。

#### 6.1.2 缺少统一的输入 schema 和唯一性校验

当前读取函数默认 CSV 字段完整且类型合法。建议在任何分析前执行预检：

- 必需文件是否存在、非空、可读取；
- 必需列是否存在；
- `submission_id`、`factor` 是否唯一且非空；
- 状态是否只包含允许枚举；
- 成功提交四个 SFA 指标是否有限；
- 分数和回归字段是否在合理范围；
- `date + instrument` 是否唯一；
- 因子池列名是否重复；
- ID 是否在 metadata 中可映射。

#### 6.1.3 没有自动生成统一结论和放行状态

目前 Notebook 需要人工阅读多个 DataFrame，容易遗漏。建议输出统一 `CheckReport`：

```text
PASS     所有阻断项为 0
REVIEW   无阻断项，但存在需人工核验的高风险项
BLOCK    存在成绩不一致、集合缺失、非法数值或平台疑似故障
```

### 6.2 P1：会影响风险识别质量的问题

#### 6.2.1 回归可疑规则过于严格

将多个风险条件压成一个 `suspicious` 布尔值，导致本轮 0 命中。应保留每项独立标签、风险分数和触发原因。

#### 6.2.2 敏感性扫描没有围绕正式参数加密

`analyze_ab_weight_sensitivity` 默认只扫描 0.0、0.1、……、1.0。对于正式 A 权重 0.3，建议至少额外提供：

- 局部扫描：0.20 至 0.40，步长 0.01；
- 全局扫描：0.00 至 1.00，步长 0.05；
- 获奖线变化：每个权重下进入或离开奖项范围的对象；
- 名次交换点：计算相邻重点提交发生反转的权重。

同时应拒绝 `steps <= 0`，避免除零错误。

#### 6.2.3 相似度只覆盖单一统计口径

应增加 Spearman、按日截面相关、缺失掩码一致率、标准化差值和全量复核，并为候选对设置最小重叠样本及重叠比例。

#### 6.2.4 失败日志分类不足

只有顶层错误和 stdout 尾部，不足以区分用户错误、资源错误和平台错误。需要结构化根因提取。

#### 6.2.5 “成功提交”判定口径不统一

部分函数读取 `summary.status == success`，部分函数使用 `final_score >= 0`。当前数据下二者一致，但长期可能分叉。建议统一以 `summary.status` 为事实来源，再显式关联榜单。

### 6.3 P2：工程性和可维护性问题

#### 6.3.1 Notebook 硬编码绝对路径

`check.ipynb` 写死本机路径和具体运行 ID，换机器或换运行后需要手工编辑。建议支持：

```python
paths = CheckPaths.discover(
    competition_id="76ad3f56-ec2b-431a-890e-139a7f4bbcba",
    run="latest",
)
```

并把解析后的绝对路径、运行时间和文件摘要打印在报告顶部。

#### 6.3.2 修改全局 `sys.path`

动态插入路径容易引入同名模块污染。更稳妥的方式是将私榜评分逻辑作为可安装包导入，或通过 `importlib.util.spec_from_file_location` 精确加载目标文件。

#### 6.3.3 读取和展示耦合

分析函数内部同时 `print`、`display` 和返回结果，不利于批处理、测试和报告生成。建议：

- 核心函数只返回结构化结果；
- 日志交给统一 logger；
- Notebook 展示放在 presentation 层；
- Markdown/CSV/PNG 导出放在 report 层。

#### 6.3.4 缺少自动化测试

至少应覆盖：

- 缺文件、缺列、重复 ID、空数据；
- NaN、正负无穷和非法状态；
- 只有成功或只有失败提交；
- 单因子和零因子场景；
- `abs_weight_mean = 0`；
- 全常数因子和低重叠因子；
- 成绩表集合不一致；
- metadata 缺参与者或联系人字段；
- `steps = 0` 和负数参数。

#### 6.3.5 可视化不可复用

当前函数直接 `plt.show()`，无法稳定用于无头执行和报告归档。建议接收 `output_path`、返回 `Figure`，并在标签中处理短 ID 冲突。

## 9. 风险分级与建议阈值

| 检查项 | INFO | WARNING / REVIEW | BLOCK |
|---|---|---|---|
| 成绩复算差异 | 0 | 不适用 | 任一差异超过 `1e-9` |
| 提交/因子/回归集合 | 完全一致 | 不适用 | 任一缺失或冗余 |
| 非有限或非法字段 | 0 | 不适用 | 任一异常 |
| 失败提交 | 用户原因且已完成规则确认 | 失败率较高或根因未知 | 疑似平台原因、批量同源失败 |
| 因子相似度 | `< 0.90` | `0.95–0.99` | 不建议自动阻断；`≥0.99` 强制人工核验 |
| A/B 局部权重敏感 | 名次变化 `< 3` | 获奖线附近变化 `≥3` | 规则未提前固定或计算口径不一致 |
| B 稳健性 | 变化 `< 5` | 获奖线附近变化 `≥5` | 正式口径与规则不一致 |
| 回归稳定性 | 无标签 | 命中低入选率、高 CV 或大排名差 | 正式结果字段非法或复跑不一致 |

高度相似因子不建议仅凭统计阈值自动阻断，因为相似不等于违规。工具应强制生成证据包，并由规则负责人给出人工结论。

## 10. 推荐的人工复核流程

### 阶段一：输入冻结与证据留存

1. 冻结运行目录，记录 run ID 和生成时间；
2. 对核心文件计算 SHA-256：
   - `submissions_summary.csv`
   - `leaderboard_final.csv`
   - `leaderboard_reg.csv`
   - `factor_pool.parquet`
   - `metadata.json`
3. 记录评分代码版本和 Git commit；
4. 禁止复核期间静默覆盖原始产物。

### 阶段二：阻断性检查

1. 输入 schema；
2. ID 唯一性；
3. 成绩复算；
4. 提交、因子池、回归集合一致性；
5. 数值范围、NaN 和无穷值；
6. 正式回归解释性复跑一致性。

任一阻断项失败，应停止放榜流程。

### 阶段三：公平性与稳健性检查

1. A/B 排名冲突；
2. 正式权重附近的局部敏感性；
3. A 指标留一法和权重扰动；
4. B 分替代口径压力测试；
5. 回归窗口稳定性；
6. 获奖线附近对象的专项分析。

### 阶段四：相似性与合规复核

1. 候选对抽样筛选；
2. 候选对全量复算；
3. 参赛方关系映射；
4. 代码和公式人工核验；
5. 记录结论、证据和审核人。

### 阶段五：失败提交处置

1. 自动分类失败根因；
2. 识别疑似平台故障；
3. 按参赛方生成联系清单；
4. 明确是否允许重跑及统一重跑条件；
5. 记录每次重跑的输入、环境和结果，避免选择性重跑。

### 阶段六：报告签署

最终报告至少应包含：

- 运行信息与文件摘要；
- 阻断项结果；
- 风险项清单；
- 失败提交处置结果；
- 高相似因子核验结果；
- 获奖线变化分析；
- 最终 `PASS / REVIEW / BLOCK`；
- 复核人、审核人和时间。
