## Overview

Only the designated data sources may be used to build factors in this competition. The evaluation program will `import` the `main` function from the code submitted by participants, and call it by passing in the data source name, start datetime, and end datetime.

## Data Sources

All data for this BigAlpha competition is hosted on the BigQuant data platform: https://bigquant.com/data/categories/-BigAlpha. Stock universe: the constituent stocks of the CSI 1000 Index at the corresponding historical points in time.


- Base data for building factors
    * 1-minute K-line and order book snapshot data. Data table link: [bigalpha_2026_stock_bar1m](https://bigquant.com/data/datasources/bigalpha_2026_stock_bar1m)
    * Financial data. Data table link: [bigalpha_2026_financial](https://bigquant.com/data/datasources/bigalpha_2026_financial)

- Other data

    * Stock list. Data table link: [bigalpha_2026_instruments](https://bigquant.com/data/datasources/bigalpha_2026_instruments)
    * Factor library. Data table link: [bigalpha_2026_factorlib](https://bigquant.com/data/datasources/bigalpha_2026_factorlib)
    * factor exposure，数据表链接：[bigalpha_2026_exposure](https://bigquant.com/data/datasources/bigalpha_2026_exposure)

## Factor Calculation Examples

### DAI Data Engine

DAI comes with a variety of built-in operators/functions. Refer to the [DAI Function Documentation](https://bigquant.com/wiki/doc/Rceb2JQBdS). DAI is an ultra-high-performance computing engine optimized specifically for AI/quant scenarios, fully leveraging the capabilities of modern CPUs/GPUs.

```
import dai

dai.query("""
    SELECT
        date::DATE::DATETIME AS date,
        instrument,
        AVG(close) / LAST(close) AS factor
    FROM bigalpha_2026_stock_bar1m
    GROUP BY date::DATE, instrument
    ORDER BY date, instrument
""", filters={"date": ["2023-01-01 00:00:00", "2023-02-01 23:59:59"]}, compression=True).df().head()
```

### UDF

The DAI data engine supports UDFs (User-Defined Functions), which allow users to extend operators by writing custom functions.

```
import dai

# Define a UDF for computing a factor - with type annotations (recommended)
def calculate_factor(instrument: str, prices: list) -> float:
    """Compute factor: average price / last price"""
    if not prices:
        return None
    
    avg_price = sum(prices) / len(prices)
    last_price = prices[-1]
    
    # Avoid division by zero
    if last_price == 0:
        return None
    
    return avg_price / last_price

# Compute the factor
dai.query("""
    WITH grouped_data AS (
        SELECT
            date::DATE::DATETIME AS date,
            instrument,
            ARRAY_AGG(close ORDER BY date) AS price_list
        FROM bigalpha_2026_stock_bar1m
        GROUP BY date::DATE, instrument
    )
    SELECT
        date,
        instrument,
        calculate_factor(instrument, price_list) AS factor
    FROM grouped_data
    ORDER BY date, instrument
""", 
filters={"date": ["2023-01-01 00:00:00", "2023-02-01 23:59:59"]}, 
compression=True,
udf_list=[
    dai.DaiUDF(
        name="calculate_factor",
        function=calculate_factor,
    )
]).df().head()
```

### Third-Party Computation Libraries

The DAI data engine also supports converting data into formats such as pd.DataFrame, pl.DataFrame, arrow, and other data types.

```
import dai

data = dai.query("SELECT date, instrument, close FROM bigalpha_2026_stock_bar1m", filters={"date": ["2023-01-01 00:00:00", "2023-02-01 23:59:59"]}, compression=True)

# Convert to a pandas dataframe, then continue computation in pandas
df = data.df()

# Convert to a polars dataframe, then continue computation in polars. polars is not built into aistudio; you can install it yourself with pip3 install polars
df = data.pl()

# Convert to apache arrow, then continue computation in arrow
df = data.arrow()

# See the DAI documentation for more
```

For more, see the DAI documentation: [DAI Documentation](https://bigquant.com/wiki/doc/PLSbc1SbZX)

### Hybrid Computation

DAI can perform hybrid computation together with pandas and others. You can use pandas, polars, arrow, and other data within DAI at high performance (bound via the `bind_relations` parameter), and JOIN and other operations are supported.

```
import dai

data = dai.query("SELECT date, instrument, close FROM bigalpha_2026_stock_bar1m", filters={"date": ["2023-01-01 00:00:00", "2023-02-01 23:59:59"]})

df = data.df()

dai.query("""
    SELECT
        date::DATE::DATETIME AS date,
        instrument AS instrument,
        AVG(close) AS avg_close
    FROM df
    GROUP BY date::DATE::DATETIME, instrument
""", bind_relations={"df": df}).df()
```

## Tips

- About dates and times
  - `date::DATE` extracts only the date part of `date`, e.g. `2025-01-03 14:24:31`::DATE is `2025-01-03`. Note: the type of `date` is TIMESTAMP, while the type of `date::DATE` is `DATE`, which may cause data type mismatch issues in some comparisons
  - `date::DATE::DATETIME` can be used to convert the data type back to `DATETIME`
  - For more date/time functions, refer to the [DAI Function Documentation](https://bigquant.com/wiki/doc/Rceb2JQBdS): `date_trunc`, `time_bucket`
- Time-series operators: functions provided by DAI. In general, functions with the `m_` prefix are time-series operators and by default compute based on `GROUP BY instrument`, e.g. `SELECT date, instrument, close / m_lag(close, 1) AS close_1 FROM bigalpha_2026_stock_bar1m`
- Cross-sectional operators: functions provided by DAI. In general, functions with the `c_` prefix are cross-sectional operators and by default compute based on `GROUP BY instrument`, e.g. `SELECT date, instrument, close / m_lag(close, 1) AS close_1, c_rank(close_1) FROM bigalpha_2026_stock_bar1m`

## Compute Resources

- Using the `compression=True` parameter can reduce memory usage: `dai.query("SELECT * FROM bigalpha_2026_stock_bar1m", filters={"date": ["2023-01-01 00:00:00", "2023-02-01 23:59:59"]}, compression=True).df()`. When the data volume is large, you can enable this parameter (set to True), and the system will automatically convert the string type of the instrument column to the category type, significantly reducing memory usage. When querying and computing pandas category types in DAI SQL, you may encounter incompatibility issues; you can try using `instrument::string` to convert it back to a string.
- Resource specifications: in the aistudio status bar, you can click on the compute resource specification to switch it. 4C/16G or higher is recommended. After entering the competition, the platform will gift you Kuan coins (宽币) for upgrading compute resources, and users can also obtain more Kuan coins by attending competition training sessions, [inviting users](https://bigquant.com/spark), and so on.
