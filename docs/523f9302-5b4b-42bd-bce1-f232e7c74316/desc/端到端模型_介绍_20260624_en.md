## Competition Introduction

**BigAlpha** is BigQuant's annual AI quantitative research competition for young talent at universities worldwide. Built on the BigQuant AI research platform, it uses real data, open problems, and professional judging to discover the next generation of fintech talent.

BigAlpha 2026 opens three competitions simultaneously worldwide, and participants are free to choose:

| Track | Suitable For | Link |
|---|---|---|
| **AI Factor Mining** | Financial engineering, quant, math, statistics | [Enter](https://bigquant.com/square/competition/76ad3f56-ec2b-431a-890e-139a7f4bbcba) |
| **End-to-End Price-Volume Time Series Forecasting** | AI, CS, data science, fintech | [Enter](https://bigquant.com/square/competition/523f9302-5b4b-42bd-bce1-f232e7c74316) |
| **AI Open Innovation** | Interdisciplinary, innovation & entrepreneurship teams | [Enter](https://bigquant.com/square/competition/63dd885c-2488-4efd-9c61-9e3a536f172c) |

**About BigQuant**: A leading AI quantitative investment platform in China, with the mission to "Democratize AI to empower investors." The platform deeply integrates AI technologies such as machine learning and deep learning with quantitative investing, providing individual quants, research institutions, brokerages, and asset managers with an end-to-end solution covering data, research, backtesting, and live trading. It has been adopted by many leading financial institutions. Core capabilities include petabyte-scale financial and alternative data, a library of 2,000+ base factors with an expression engine, the high-performance DAI data engine, and a strategy source-code library with live-trading integration. This track uses the same toolchain as institutional clients.

**Why end-to-end models**: The traditional two-step paradigm of "factor mining + portfolio optimization" relies heavily on human expertise to construct features, making it hard to capture the rapidly changing nonlinear, high-order interactions in markets, and facing the dual challenges of information loss and human bias. **End-to-End quantitative modeling** uses deep neural networks to skip tedious explicit feature engineering, learning investment logic directly from raw market sequence data and achieving a one-stop mapping from "raw data" to "investment decisions." This track focuses on **end-to-end model generation**: participants no longer mine isolated factors, but instead build large models capable of handling complex spatiotemporal relationships, taking the multi-frequency minute-level market data provided by the organizers as input and stock residual returns as the target. We encourage a feature-free or feature-light development approach that uses raw price-volume sequences (such as OHLCV and intraday snapshots) as much as possible, letting the model's internal mechanisms spontaneously capture the deep patterns of market microstructure.

## Data

* **Stock Universe**: Constituents of the CSI 1000 Index at the corresponding historical points in time.
* **Time Range**: 2019-01-01 to 2023-12-31.
* **Data Content**: 1-minute / 5-minute / 15-minute / 30-minute K-line and order-book snapshot data.

## Participation and Submission

### Template Code

This track uses an "end-to-end model generation" approach: participants build models according to the specifications and submit training / inference code. The organizers provide the following templates for reference:

| Template | Description |
|---|---|
| `Transformer.ipynb` | Trains a transformer model in real time |
| `Transformer_modelsave_train.ipynb` | If training takes too long, save the model and submit it together. (Local training code; please convert to a .py file when submitting.) |
| `Transformer_modelsave_predict.ipynb` | If training takes too long, save the model and submit it together. (Prediction module.) |

> Note: You may submit multiple files of different types, but the code that calls the evaluation module must be placed in a notebook, and there can be only one notebook in the submission. The backend will extract and run the code within it.

### Model Specifications

**Input and Feature Constraints**

1. **Feature Cap**: Model input fields must not exceed **100 raw fields**. The same field at different time steps within a time-series window still counts as 1 field (i.e., the sequence length is not counted toward the field count).
2. **Data Source**: All input fields must come directly from the data provided by the organizers. **Any derived or manual feature engineering is prohibited**, including cross-field operators, rolling statistics, factor synthesis, dimensionality reduction, third-party data, etc.
3. **Allowed Preprocessing**: Missing-value imputation, per-field uniform normalization (MinMax / StandardScaler), and per-field uniform logarithmic or sign transformations. Preprocessing parameters may only be derived from training-set statistics.
4. **Time-Series Window Cap**: The look-back window for a single inference must be ≤ **240 trading days**.

**Model Architecture Constraints**

1. **Trainable Parameters**: ≥ 100,000 (100K), ≤ 100,000,000 (100M).
2. **External Pretrained Weights**: The use of any external pretrained weights is prohibited. All parameters must be trained from scratch by participants based on this competition's data.
3. **Architecture Form**: Not strictly specified, but the combination of the minimum parameter count and the ban on feature engineering means that shallow models (XGBoost, linear models) will struggle to achieve competitive results.

### Submission Format

Each model inference submission produces a score file that must contain exactly three columns (by default, higher scores are better; participants must ensure the sign is correct):

| date | instrument | score |
|---|---|---|
| 2023-01-03 | 000001.SZ | 0.05 |
| 2023-01-03 | 000002.SZ | -0.12 |

> The resulting scores, after style removal, are equivalent to a daily-updated single factor, so the single-factor score is directly used as the team's score.

### Data Validation

The submitted score file must pass all of the following validations, or it will be deemed invalid:

* **Data Columns**: Column names must strictly match the three columns `date`, `instrument`, and `score`, with no extra columns.
* **Trading-Day Completeness**: No trading day within the evaluation period may be missing.
* **Cross-Sectional Coverage**: The score missing rate per trading day must not exceed **40%**.

### Platform Preprocessing

After validation passes, the platform uniformly processes the raw scores in the following order:

1. **Outlier Removal**: Cross-sectional 1% / 99% percentile winsorization.
2. **Standardization**: Cross-sectional z-score.
3. **Style Removal**: Run a cross-sectional regression of the standardized scores against BARRA risk factors (size, Beta, momentum, volatility, liquidity, valuation, profitability, growth, leverage, nonlinear size), **taking the residual as the final evaluation target**.

### Runtime Environment Requirements

To ensure fairness, all code must run and be submitted in the designated online BigQuant Notebook environment. Every submission must be a complete code package that automatically runs the inference script and generates the score file:

* **Runtime**: GPU Notebook ≤ 6 hours (public-leaderboard single-inference cap is 12 hours).
* **No External Network**: To prevent information leakage and the use of future data, internet access is disabled in the Notebook.

## Scoring Mechanism

The resulting scores, after style removal, are equivalent to a daily-updated single factor, and the team's score is that single-factor score.

### Final Score Formula

$$\text{Score}_{\text{final}} = 0.25 \times \text{Rank}_{IC_{mean}} + 0.25 \times \text{Rank}_{IC_{IR}} + 0.25 \times \text{Rank}_{SR} + 0.25 \times \text{Rank}_{\text{Stress}}$$

* $\text{Rank}_{IC_{mean}}$: The overall ranking of the mean cross-sectional IC over the evaluation period.
* $\text{Rank}_{IC_{IR}}$: The ranking of the IR (mean IC / standard deviation of IC) of the IC series.
* $\text{Rank}_{SR}$: The ranking of the annualized Sharpe ratio of the long-short 10-group portfolio built from the model scores.
* $\text{Rank}_{\text{Stress}}$: The ranking of robustness evaluated per regime.

> All four items are percentile-normalized and then summed with equal weights; teams are ranked in descending order of $\text{Score}_{\text{final}}$ to obtain the final ranking.

## Evaluation Cycle and Ranking

The competition has two stages, a **public leaderboard** and a **private leaderboard**, using different data periods. The final ranking is based on the private leaderboard.

### Data Split

| Stage | Training Set | Validation Set | Description |
|---|---|---|---|
| Public | 2019-01-01 ~ 2023-12-31 | 2024-01-01 ~ 2024-12-31 | Validation scores are visible, used for debugging and iteration |
| Private | Not disclosed | Not disclosed | Includes out-of-sample data, used for final ranking |

### Submission Rules and Frequency

**Public Leaderboard Stage**:

* **Each submission must be a complete model package**, including the training script, inference script, dependency declarations, hyperparameter configuration, random seeds, and the **trained weights** obtained on the public-leaderboard training set. During the public-leaderboard stage, the platform **only runs inference based on the submitted weights** and does not retrain, thereby sparing participants the repeated training cost caused by platform retraining.
* Each team may submit at most **3 times per day** (including failed submissions).
* Submissions **do not override each other**: each submission is stored as an independent record, scored via inference over the public-leaderboard period, and its score is displayed. Participants may simultaneously hold and iterate on multiple candidate models, without needing to pre-select a particular set of weights during iteration.
* Before the public leaderboard closes, each team must **designate a single unique end-to-end model** from its submission history as the private-leaderboard entry; if no designation is made by the deadline, the platform defaults to the team's highest-scoring public-leaderboard submission. Once a designation is confirmed, it is frozen, and participants may not add or modify its code, configuration, or dependencies.

**Private Leaderboard Stage**:

1. **Platform Retraining**: In an isolated environment, the platform **retrains this unique model from scratch** using a specific training set, following the participant's submitted training script and configuration. The participant's submitted public-leaderboard weights do not participate in the private-leaderboard evaluation.
2. **Private Inference**: The retrained weights are used to run inference and score over the private-leaderboard validation period, and that score becomes the final ranking.

### Per-Round Published Content

At a fixed time each day during the public-leaderboard stage, the following information is published based on the latest evaluation results, to help participants clarify their optimization direction.

**(1) Model Profile** (the top 10 submissions by total public-leaderboard score, deduplicated by team, with only each team's current highest-scoring submission taken)

| Feature | Description |
|---|---|
| BARRA Style Exposure | The exposure distribution of the model's pre-style-removal scores across styles such as size, Beta, momentum, and volatility |
| Industry IC Distribution | The model's average IC across SW first-level industries, revealing industry preferences |
| Cross-Sectional Dispersion | The time-series mean of the cross-sectional std of scores, measuring whether predictions are overly concentrated |

> What is published are **aggregate features**, which do not involve the specific network architecture and do not affect intellectual property protection.

**(2) Team Detailed Scores**

* The total score of **each valid submission** by this team, the overall percentile of the four sub-items (IC mean / IC_IR / SR / Stress), and this team's current highest-scoring submission.
* A breakdown of the gap between the current highest-scoring submission and the 1st-place and 10th-place sub-item scores, to locate the weakest item.
* The score trajectory over the last 30 evaluation days (aggregated by submission, with the option to switch and view the trajectories of this team's different submissions).

**(3) Index Enhancement Strategy Tracking**

Based on the score of each team's **current highest-scoring public-leaderboard submission**, the platform simultaneously builds a **CSI 1000 index enhancement strategy**: using the model score as the signal, it overweights high-scoring stocks and underweights low-scoring stocks within the constituents, with a tracking-error constraint within about 5%. After each evaluation round, the holdings are updated and displayed:

| Metric | Description |
|---|---|
| Cumulative Excess Return | Cumulative alpha relative to CSI 1000 |
| Information Ratio (IR) | Annualized excess return / tracking error |
| Maximum Drawdown | The maximum drawdown of excess returns |
| Incremental Contribution | The change in the strategy's IR after the new submission |

> If an end-to-end model truly extracts incremental information from raw data, it should be able to continuously push up the index-enhancement strategy's IR; if an iteration fails to improve the strategy's performance, that will also be presented faithfully, as feedback to participants.

## Finals

### Submission Materials

Shortlisted teams must submit a model research report (PDF, 10–15 pages) by the deadline, structured to include:

| Section | Key Content |
|---|---|
| Abstract | Research objectives, core methods, and main conclusions |
| Introduction | Research background and literature review |
| Model Construction | Detailed account of model-building details (data processing, network structure, training strategy) |
| Innovation and Limitations | Discussion of methodological innovations and limitations |
| Conclusion | Research summary and future directions |

### Defense and Awards

The finals defense uses a **"25-minute presentation + 5-minute judge Q&A"** format, held offline with a simultaneous live stream online. After the defense, the final rankings are announced and an awards ceremony is held, inviting all guests, judges, and contestants to participate together.

### Evaluation Criteria

The review committee evaluates comprehensively:

* **Model Quality and Logic**: Modeling approach and effectiveness; robustness and statistical significance across cycles and industries.
* **Research Depth and Rigor**: The rigor of the report structure and depth of analysis; code quality, readability, and reproducibility.
* **On-Site Performance**: The clarity and organization of the presentation; the precision and logic of the Q&A.
* **AI Innovation**: The originality of the model architecture and technical choices; the depth of modeling market microstructure and its practical effectiveness.
